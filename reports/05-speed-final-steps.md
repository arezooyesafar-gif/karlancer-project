# رسیدن به امتیاز بالای ۹۰: قدم‌های پایانی سرعت

- تاریخ: ۹ مهر ۱۴۰۵

## ۱. وضعیت تا الان

| | قبل | الان |
|---|---|---|
| ساخت صفحهٔ دسته‌بندی وقتی در کش نیست | ۴۰ ثانیه | **۵ ثانیه** |
| همان صفحه وقتی از کش LiteSpeed سرو می‌شود | – | **زیر ۰٫۳ ثانیه** |
| تصویر اصلی صفحهٔ محصول | تا ۵٫۷ ثانیه دیر لود می‌شد (lazy-load) | بلافاصله لود می‌شود |

## ۲. چرا امتیاز Lighthouse هنوز پایین بود

همهٔ تست‌های Lighthouse در **اولین بازدید** گرفته شدند، یعنی وقتی صفحه هنوز در کش نبود. در تفکیک LCP صفحهٔ خانه، از ۳٫۹ ثانیه، **۳٫۸ ثانیه** فقط انتظار برای سرور بوده است. حتی Speed Index (۸ تا ۱۸ ثانیه) هم از همین انتظار بالا رفته، چون تا وقتی سرور جواب ندهد صفحه سفید می‌ماند.

**پس مهم‌ترین قدم:** باید مطمئن شویم صفحه‌ها **همیشه در کش هستند**، هم برای بازدیدکننده و هم برای ابزار تست.

## ۳. کارها

### الف) فایل (آپلود)

`performance-config.php`: دو فونت اصلی متن (IRANYekanX Regular و DemiBold) از اول همراه CSS دانلود می‌شوند (preload)، نه بعد از آن. فونت‌ها همان فایل‌ها هستند، پس ظاهر متن تغییری نمی‌کند.

### ب) تنظیمات LiteSpeed Cache

| بخش | گزینه | مقدار | چرا |
|---|---|---|---|
| Cache | Enable Cache / Cache Mobile | ON / ON | |
| Cache ← Browser | Browser Cache | ON | فایل‌ها برای بازدید دوم دوباره دانلود نشوند |
| **Crawler** | Crawler | **ON** | صفحه‌ها قبل از بازدیدکننده در کش ساخته شوند |
| Crawler | Custom Sitemap | `https://zioma.ir/sitemap_index.xml` | نقشهٔ سایت Yoast |
| Crawler | Server Load Limit | همان مقدار پیش‌فرض (پایین) | CPU هاست نزدیک سقف است |
| Page Optimization ← CSS | CSS Minify / CSS Combine | ON / ON | ۴۰ فایل CSS یکی می‌شوند |
| Page Optimization ← JS | JS Minify | ON | |
| Page Optimization ← Media | Lazy Load Images | ON | |

**این گزینه‌ها را روشن نکنید**، چون ظاهر را هنگام لود تغییر می‌دهند یا روی این سرور کار نمی‌کنند:
- UCSS، Load CSS Async و Load JS Delayed
- Guest Mode، Guest Optimization و Font Display
- بهینه‌سازی تصویر QUIC.cloud، چون سرور به سرویس‌های خارجی دسترسی ندارد

اگر در بخش Crawler پیام **disabled by server admin** دیدید، باید از میزبان‌فا بخواهید Crawler را برای حساب فعال کند.

### ج) روش درست تست

1. بعد از Purge All، صبر کنید Crawler یک دور کامل اجرا شود. اگر نمی‌خواهید صبر کنید، هر صفحه را یک بار در پنجرهٔ ناشناس باز کنید: یک بار با نمای موبایل (F12 و آیکون گوشی) و یک بار عادی.
2. Lighthouse را **دو بار** روی هر صفحه اجرا کنید و **نتیجهٔ دوم** را ملاک بگیرید.
3. JSON نتیجه‌ها را بفرستید تا قدم آخر (کاهش فایل‌های JS و CSS هر صفحه) را بر اساس آن انجام دهم.

## ۴. انتظار واقع‌بینانه

| | دسکتاپ | موبایل |
|---|---|---|
| امتیاز Lighthouse با کش | **۹۶ تا ۱۰۰** | حدود **۹۰ تا ۹۵** برای خانه و دسته‌بندی |
| زمان لود با کش | **زیر ۱ ثانیه** | حدود **۲ ثانیه** روی 4G |

**سقف موبایل:** چند چیز با شرط «بدون تغییر ظاهر» قابل حذف نیستند:
- اسلایدرها و تایمرهای تخفیف که دائم حرکت می‌کنند (Speed Index)
- دو فونت آیکون جمعاً حدود ۴۰۰ کیلوبایت
- آنالیتیکس گوگل با ۱۵۷ کیلوبایت

صفحهٔ محصول موبایل یک جابه‌جایی صفحه (CLS = 0.29) هم دارد که تا اصلاح نشود، حدود ۱۵ امتیاز از آن کم می‌کند. برای اصلاحش HTML همان صفحه لازم است: در حالت موبایل، Ctrl+S و «Webpage, HTML only».
