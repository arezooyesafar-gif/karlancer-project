# مرحلهٔ ۱: آپلود روی هاست و تست

این مرحله سه کار انجام می‌دهد:

- اصلاحیهٔ باگ لوپ صفحه‌ها با کش LiteSpeed روی سایت می‌رود.
- زیرساخت حذف JS و CSS به‌صورت mu-plugin نصب می‌شود.
- ابزاری روی سایت قرار می‌گیرد که خطاهای کنسول، فایل‌های گم‌شده و درخواست‌های Ajax هر صفحه را ثبت می‌کند. شما گزارش این ابزار را برای من کپی می‌کنید و مرحلهٔ بعد (رفع باگ لود بیشتر و حذف فایل‌های اضافه) بر اساس همان انجام می‌شود.

هیچ‌کدام از این تغییرات ظاهر سایت را عوض نمی‌کند. ابزار بررسی فقط برای ادمین و فقط با یک پارامتر خاص در آدرس دیده می‌شود.

**تست‌هایی که انجام شده:**
- بررسی نحوی (syntax) همهٔ فایل‌های PHP
- اجرای کد با یک وردپرس شبیه‌سازی‌شده
- اجرای ابزار بررسی در کروم

**تستی که انجام نشده:** روی سایت واقعی تست نشده است. برای همین اول ساب‌دامین تستی، بعد سایت اصلی.

---

## ۰. قبل از هر کاری

1. از **فایل‌ها و دیتابیس** بکاپ کامل بگیرید، از بخش Backup در cPanel یا بکاپ هاست.
2. از این صفحه‌ها در موبایل و دسکتاپ اسکرین‌شات بگیرید تا بعداً ظاهر را مقایسه کنید:
   - خانه
   - یک دسته‌بندی
   - یک محصول
   - سبد خرید
   - تسویه حساب
   - یک مطلب بلاگ

## ۱. فایل‌هایی که باید آپلود شوند

کدها داخل یک **mu-plugin** قرار دارند، نه داخل چایلد تم. mu-pluginها بدون فعال کردن و با هر پوسته‌ای اجرا می‌شوند و با آپدیت قالب یا افزونه‌ها هم پاک نمی‌شوند. پس لازم نیست پوسته عوض شود.

> **پوسته را عوض نکنید.** همان «پارس کالا» فعال بماند. تنظیمات Customizer، منوها و ابزارک‌ها به پوستهٔ فعال بسته‌اند و فعال کردن چایلد تم ممکن است ظاهر سایت را تغییر دهد.

| فایل | مقصد روی هاست | روش |
|---|---|---|
| `zioma-performance.php` | `public_html/wp-content/mu-plugins/` | فایل جدید، کنار `mfa-autologin.php` |
| پوشهٔ `zioma/` با ۴ فایل: `cache-compat.php`، `performance.php`، `performance-config.php` و `asset-inspector.php` | `public_html/wp-content/mu-plugins/zioma/` | پوشهٔ جدید |
| بلاک `# BEGIN Zioma` تا `# END Zioma` | ابتدای `public_html/.htaccess` | اگر قبلاً paste کرده‌اید، کاری لازم نیست. فقط مسیر داخل کامنتش عوض شده است. |

**پاک‌سازی نسخهٔ قبلی** (فایل‌هایی که قبلاً داخل چایلد تم آپلود کردید):
- `public_html/wp-content/themes/parskala-child/functions.php` را با نسخهٔ جدید جایگزین کنید. نسخهٔ جدید فقط یک توضیح دارد.
- پوشهٔ `public_html/wp-content/themes/parskala-child/inc/` را حذف کنید.

اگر این دو کار انجام نشود و کسی بعداً چایلد تم را فعال کند، سایت خطا می‌دهد، چون همان کد دو بار بارگذاری می‌شود.

> ⚠️ **این فایل‌ها را از ریپو روی هاست آپلود نکنید:**
> - `wp-config.php`: در ریپو رمز دیتابیس و کلیدها `REMOVED` است. اگر آپلود شود، سایت از کار می‌افتد.
> - کل فایل `.htaccess`: نسخهٔ روی هاست ممکن است بلاک LiteSpeed داشته باشد و نباید پاک شود.
> - `php.ini`، `.user.ini`، `robots.txt` و `mfa-autologin.php`: این‌ها تغییری نکرده‌اند.

**بعد از آپلود:**
1. در پیشخوان وردپرس به «افزونه‌ها» بروید. باید یک تب **«ضروری» (Must-Use)** ببینید که «Zioma Performance» در آن هست.
2. سایت را در یک پنجرهٔ ناشناس (Incognito) باز کنید. سایت باید دقیقاً مثل قبل باشد.

**اگر سایت سفید شد یا خطا داد:** در File Manager فایل `mu-plugins/zioma-performance.php` را حذف کنید یا اسمش را به `zioma-performance.php.off` تغییر دهید. سایت به حالت قبل برمی‌گردد. متن خطا را برای من بفرستید.

## ۲. تست باگ ۱ (لوپ صفحه‌ها با کش)

1. در LiteSpeed Cache فقط این تنظیمات را بدهید. **بقیهٔ گزینه‌ها فعلاً خاموش بمانند:**
   - **Cache ← Cache:**
     - Enable Cache = ON
     - Cache Logged-in Users = OFF
     - Cache REST API = OFF
     - Cache Mobile = **ON**
   - **Cache ← ESI:** Enable ESI = OFF
   - **Cache ← Browser:** Browser Cache = ON
   - **Page Optimization:** همهٔ گزینه‌ها OFF، یعنی:
     - Minify و Combine برای CSS و JS
     - UCSS و Load CSS Async
     - Load JS Deferred یا Delayed
     - HTML Minify
     - Guest Mode و Guest Optimization
2. در Toolbox دکمهٔ **Purge All** را بزنید. اگر CDN دارید، آن را هم Purge کنید.
3. **با پنجرهٔ ناشناس** (نه با حساب ادمین، چون کش برای ادمین نمایش داده نمی‌شود) این دو صفحه را باز کنید و تا انتها اسکرول کنید. این کار را هم روی دسکتاپ انجام دهید و هم روی یک موبایل واقعی:
   - صفحهٔ اصلی
   - یک دسته‌بندی
4. نتیجه:
   - **لوپ نیست و ظاهر درست است:** باگ ۱ حل شده است. کش را روشن نگه دارید.
   - **هنوز لوپ هست:** کش را خاموش کنید. در همان پنجرهٔ ناشناس کلید F12 را بزنید، به تب Network بروید و فیلتر Fetch/XHR را انتخاب کنید. اسکرول کنید، روی درخواستی که ظاهر می‌شود کلیک کنید و از بخش Headers و Response اسکرین‌شات بگیرید و برای من بفرستید.

## ۳. گرفتن گزارش صفحه‌ها برای مرحلهٔ بعد

در حالی که **با حساب ادمین** وارد سایت هستید، هرکدام از این آدرس‌ها را باز کنید. در انتهای آدرس `?zioma_assets=1` بگذارید، یا اگر آدرس از قبل `?` دارد، `&zioma_assets=1`:

| صفحه | نمونه |
|---|---|
| خانه | `https://zioma.ir/?zioma_assets=1` |
| یک دسته‌بندی محصول | `https://zioma.ir/product-category/…/?zioma_assets=1` |
| یک محصول | `https://zioma.ir/product/…/?zioma_assets=1` |
| سبد خرید (یک محصول در سبد بگذارید) | `https://zioma.ir/cart/?zioma_assets=1` |
| تسویه حساب | `https://zioma.ir/checkout/?zioma_assets=1` |
| یک مطلب بلاگ | `…/?zioma_assets=1` |

**برای هر صفحه:**
1. پایین صفحه یک نوار سفید باریک ظاهر می‌شود. فقط ادمین آن را می‌بیند.
2. در **صفحهٔ دسته‌بندی** تا انتهای صفحه اسکرول کنید و **۵ ثانیه صبر کنید**. این گزارش علت باگ لود بیشتر را نشان می‌دهد.
3. روی دکمهٔ **Copy report** در نوار بزنید و متن را در چت برای من paste کنید. اگر کپی نشد، یک کادر متن باز می‌شود؛ متن داخل آن را کپی کنید.

این گزارش شامل فهرست فایل‌های CSS و JS، خطاهای کنسول، فایل‌هایی که لود نشده‌اند و درخواست‌های Ajax است. **رمز یا اطلاعات ورود در آن نیست.**

اگر گزارش را از **موبایل** هم بگیرید (با همان حساب ادمین) بهتر است، چون پارس‌کالا برای موبایل فایل‌های جدا لود می‌کند.

---

## ۴. کاری که بعد از رسیدن گزارش‌ها انجام می‌دهم

1. علت قطعی باگ لود بیشتر در دسته‌بندی‌ها را از روی خطاها و درخواست‌ها درمی‌آورم و اصلاحش را داخل همین mu-plugin می‌نویسم.
2. فهرست JS و CSS‌ای را که در هر نوع صفحه لازم نیست داخل `performance-config.php` پر می‌کنم. با آپدیت قالب پاک نمی‌شود و به افزونه نیازی ندارد.
3. تنظیمات مرحله‌به‌مرحلهٔ Page Optimization و Lazy Load را می‌دهم. هر گزینه جدا روشن و تست می‌شود تا ظاهر تغییر نکند.

**مقایسه با حالت بدون تغییرات:** ادمین می‌تواند هر صفحه را با `?zioma_perf=off` بدون این تغییرات ببیند و با حالت عادی مقایسه کند.
